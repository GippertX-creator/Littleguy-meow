# V0.2 动画、性能与验收

本文件描述待实现的目标与检查方法，没有新增已通过的 V0.2 运行或性能成绩。

## 尺度和运动

以屏幕中猫的身长 B（不含尾巴）为尺度，避免调整大小后步速和距离失衡。以下典型 DIP 值按 B=200 估算，实际按显示大小缩放，物理像素再由显示器 DPI 换算。

| 参数 | 相对身长 | B=200 时的典型值 |
| --- | --- | --- |
| 慢走速度 | 0.25–0.40 B/秒 | 50–80 DIP/秒 |
| 轻快走速度 | 0.45–0.65 B/秒 | 90–130 DIP/秒 |
| 短距离追逐上限 | 0.90–1.40 B/秒 | 180–280 DIP/秒 |
| 小跳高度 | 0.05–0.12 B | 10–24 DIP |
| 小跳一次时长 | — | 0.30–0.50 秒 |
| 普通转向 | — | 0.35–0.80 秒，先转头再踏步转身 |
| 起身 / 趴下 | — | 约 0.8–1.6 秒，按姿势调节 |

路径位置用二维工作区坐标表示；跳跃另有离地高度，投影到屏幕时体现在身体与地面接触点的相对位置。跳跃的高度曲线、身体形变和落地弯肘分别设计，不能仅给整张图片叠一个正弦位移。所有窗口移动保留浮点累积，呈现时再转像素，避免慢走出现零步和整数抖动。

## 动作片段与接地

制作以下连续片段，所有循环的首尾位置、速度和四肢相位必须接得上：

- 慢走循环、轻快走循环、启动、制动和小碎步转身。
- 小跳预备、蹬地、腾空、前爪着地、后腿跟上和恢复步行。
- 腹趴起身、侧躺起身、蜷睡展开起身、仰躺翻回侧躺再起身。
- 站立趴下、腹趴转侧躺、侧躺转仰躺、侧躺蜷起及相应回程。
- 注意光标、压低身体、追逐、减速、拍爪、小扑、放弃后整理爪子。
- 可以叠加的眨眼、耳朵转向、呼吸、尾尖轻动和打哈欠。

慢走是四足交替承重；轻快走也要有清楚的支撑期。需要小跑时单独制作对角肢配合，不能把慢走循环简单快放后当作另一种步态。前后肢步频与地面速度一致，支撑爪在支撑期内固定在相应地面点。离地的爪按弧线抬起、前送、落下，躯干通过肩胛、脊柱和骨盆的曲线跟随。

头、胸、腹、骨盆、尾巴根与四肢有稳定命名的骨骼/网格控制点；照片不够的关节按猫的解剖补足。长毛使用边缘和局部网格的轻微延迟，不采用全身橡皮伸缩。大幅转向和翻身使用与当前视角匹配的桥接片段，不能把一种身体朝向连续拉扯成另一种。

运行素材显式记录帧矩形、骨架或网格控制、朝向、脚底/根节点锚点、支撑爪区间、事件和有效命中遮罩。V0.1 的自动轮廓分离可继续用于素材整理，不再作为复杂多帧动画的唯一索引；不能把概念板中的文字、相邻姿势或阴影读进成品。

## 更新与渲染

逻辑采用固定 1/120 秒步进，决策和冷却基于秒，不基于帧数；每次呈现对相邻逻辑状态插值。休眠恢复只接纳有限时间步，不补跑几小时的散步；后台和暂停状态不忙循环。

渲染默认跟随显示器刷新，支持 60、120、144 FPS 档和自动模式，自动模式上限 144。显卡不能稳定达到目标时按 144→120→60 降档，并保留用户选择；不能用快速重复提交相同静态图冒充连续动作。

候选呈现结构：C# 行为与素材播放器 + 原生透明宠物窗口 + GPU DirectComposition/Direct2D 呈现；WPF/WinForms 继续管理设置与托盘。行为层只输出位置、动画片段、相位和姿势权重，避免依赖特定界面计时器。先做一只猫的原生透明窗口性能样机，确认当前机器和高刷显示器上的实际效果，再固定最终后端。

素材离线完成裁切、图集布局和颜色空间设置；运行时提前上传当前片段及下一过渡的纹理。渲染回调不做磁盘读取、PNG 解码、联网、设置保存或大型内存分配。使用预乘透明度以减少毛边黑线，避免每帧跨显卡/CPU 复制整张大位图。稳定大小的渲染窗口和呈现区域应在样机中与命中穿透一起验证。

原始关键帧数量与显示 FPS 分别记录。骨架曲线可以在每次呈现时求值；对完整位图片段至少制作足以支撑动作的中间帧，并按实测避免重复停顿。不可将“24 张原画每秒”写成“144 张独立动作帧”。

## 行为优先级与中断

退出始终优先。拖动/手动摸摸、暂停、安静模式优先于自主散步和追逐。拖动直接进入被抱起状态，放下后重新建立落点；暂停冻结当前动作和计时。安静模式让当前腾空动作先落地、再休息，不停在半空。菜单打开时不突然自动开追。

已在主动玩耍时暂时抑制普通受惊触发，防止同一光标既被追又反复吓到猫。追逐到上限、到边缘、目标不可用或用户切换安静模式时，走制动与恢复路线。临时穿透和用户手动穿透设置分开管理，退出行为时必须恢复用户原设置。

## Windows 验收门槛

### 行为正确性

- 在正常活跃度下实际观察到慢走、轻快走和少量小跳，三者自然衔接，空闲时仍以休息为主。
- 追逐有随机间隔和冷却，默认一轮 2–6 秒，不持续黏着光标；长时间离开、重启、暂停或全屏恢复后不爆发积攒的追逐。
- 猫的身体不抢真实点击，追逐结束后可恢复摸摸和拖动；托盘可随时停止、退出或找回。
- 24 个自主卧姿一轮恰好各出现一次，跨轮最近 8 个不重复；正常重启后顺序延续。人为选姿势不破坏自动队列。
- 在不同帧率和随机种子下检验速度、追逐频次、冷却及暂停语义一致；保存损坏时安全恢复默认而不崩溃。
- 多屏、负坐标、100%/150%/200% DPI、不同刷新率、显示器断开和休眠恢复不丢猫、不瞬移。

### 连贯性

- 起身到迈步、慢走到小跳、小跳到着地、站立到趴下、趴到侧躺/仰躺，都有实际中间运动。
- 按四分之一播放速度检查支撑爪：不能沿地面明显滑动，落地不穿地，腿数、关节方向与毛色不跳变。
- 面朝左右切换经过转向片段，不瞬间镜像；身体体积、头身比例和尾尖颜色保持一致。
- 素材预加载充分，第一次追逐和第一次切到某个卧姿不出现解码卡顿。

### 性能目标（待实测）

固定一台注明 CPU/GPU、内存、Windows 版本、DPI 和刷新率的参考机器，分别以 60/120/144 Hz 实测 10 分钟。用实际呈现/帧间隔数据，必要时结合 PresentMon/ETW，不只统计回调次数。高刷测试要求相应高刷屏。

- 高质量模式尽量贴合所选刷新率；帧间隔 p95 不大于一个显示周期的 1.25 倍，超过两个显示周期的帧低于 1%。性能不足时应明确降档。
- 移动过程中不因后台保存、首次加载或跨屏发生可见长停顿；预加载后不出现超过 100 毫秒的单帧停滞。
- 一个默认大小宠物，工作集以 256 MiB 以内、纹理预算以 128 MiB 以内为初始优化目标；在 8 逻辑线程参考机上平均整机占比 CPU 以 3% 以内为目标，休息和节能模式应更低。
- 若真实呈现、资源占用或素材连贯性达不到以上目标，不能仅显示一个“144 FPS”标签就通过验收。记录结果并修正后端、贴图或动作。
